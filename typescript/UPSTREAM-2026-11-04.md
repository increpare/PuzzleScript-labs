# Active source capture after comments

The immutable vanilla oracle now pins local source-only commit
`7417d78a75b5a07402071e21e0c171a76ef8871d` on `codex/comment-rule-capture`,

Previously, closing a leading comment could reenter RULES or WINCONDITIONS at
logical start of line, but an unanchored whole-line search could capture text
inside the comment. The parser now captures from the active cursor once per
physical line. Authored offsets account for Unicode lowercase expansion;
message casing and literal parentheses are retained. Inline trailing comments
end the capture without reactivating a suffix or opening comments in ignored
text. Section-heading validation still examines text after comments.

The TypeScript lexical walk and authored reader implement the corrected
behavior directly. Leading nested/multiline comments remain supported, and an
unmatched leading close cannot create an executable rule. Both default quirks
and `noQuirks` use the corrected source capture.
