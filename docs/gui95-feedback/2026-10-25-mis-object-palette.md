# GUI95 feedback — object palette overflow

- User evidence: Heroes of Sokoban and Castle Closet screenshots show a one-line palette clipped at the right edge and a board centered far outside the visible designer.
- Reference: GUI95's maintained toolbar wraps, Vector95's toolbox uses fixed-size buttons in an auto-filling grid, and its split-pane guidance constrains scrolling children with zero minimum sizes. Applying this to MIS means wrapping object tiles into rows and containing any further scrolling within the palette.
- Confirmed cause: the designer's implicit auto-width grid column takes its minimum size from the toolbar. At a 1360 px viewport with a wider code pane, the designer measured 545 px wide while its board area was 610 px wide, extending underneath the code pane. The canvas was correctly centering itself in the wrong-sized area.
- Fix: give the designer a `minmax(0,1fr)` internal column. Wrap fixed 28 px object buttons; cap the palette at 100 px with its own vertical scrollbar and contain wheel scrolling there. No canvas centering changes were necessary.
- Verification: Chrome and Playwright WebKit passed both games at scales 1, 1.25, 1.5 and 2, with default and narrowed designer widths (32 cases), both locally and on `https://www.puzzlescript.net/mis/`. Castle Closet's 39 object tiles used up to four rows; the last tile remained reachable through the capped palette. Board bounds/centering, palette height, page width and fixed tile sizes passed. Screenshot evidence is in `build/mis-palette-checks/`. Both public entry points also passed nine demos, native solving and suggestion generation.
- Test findings: an initial fixture incorrectly required wrapping even when all 18 Heroes tiles fit; the regression was corrected to require wrapping only when necessary, then reproduced the 610 px board area inside a 545 px section. The first live WebKit pass completed all geometry assertions but reported canceled WASM downloads when the test immediately navigated away. Waiting for worker-ready messages before navigation resolved the test race; the final 32 live cases completed without browser exceptions.
- Reusable lesson: clipping a palette does not constrain a grid track's intrinsic width; the workspace column and the tool palette both need explicit bounds.
- Limits: WebKit is an engine check, not installed Safari; no Windows or repackaged desktop app check. Reference behavior is a modern GUI95 adaptation, not a universal historical Windows rule.
- Status: deployed to the authorized PuzzleScript URL with replaced files backed up outside the web root; no unresolved defect in the checked browsers.
