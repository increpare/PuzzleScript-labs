# PuzzlePocket — Controller PCB Silkscreen

Date: 2026-08-01
Status: agreed in design session (HTML preview locked).

## What this covers

Decorative and functional silkscreen on the PuzzlePocket **controller PCB**
(`hardware/pocket_card/case/`, generated by `pcb.py` / `silk.py`). Product
facing name is **PuzzlePocket** (not the internal “pocket card” string).

Numeric layout truth remains in `params.py`. Silk content and packing live in
`silk.py` + `silk_rules_corpus.txt`.

## Constraints

| Topic | Decision |
|---|---|
| Ink | Binary on/off only (white or black epoxy). No greyscale, no opacity tricks. |
| Fab | Target JLCPCB-class DFM: character height ≥ **1.0 mm** preferred (absolute floor 0.8 mm); stroke ≥ 0.15 mm. |
| Pads | Do not rely on silk over pads; fab clips to solder-mask openings. Keep legends clear of pads where practical. |
| Preview vs Gerber | Preview “masks” paint FR4 over ink. Real generation **omits** lower-layer ink inside higher-layer keepouts. |

## Layer stack (both F.SilkS and B.SilkS)

Bottom → top. Each layer clears (omits) lower ink in a keepout around its marks:

1. **BG** — Solid brick motif tiled over the **whole** board.
   Motif (5×5 cells, `1` = ink), cell ≈ **0.32 mm**:
   ```
   11111
   00100
   11111
   01000
   01000
   ```
   Drawn as merged solid bars (not speckled single-cell noise).

2. **RULES** — Full PuzzleScript rule lines scraped from `src/demo/*.txt`.
   - Exclude any line containing `rigid`.
   - Never truncate a line; only place rules that fit the column width.
   - Prefer iconic lines (push crate, late match-3, fruit, trail, VBeam, …).
   - Each placed rule gets one **axis-aligned bounding-box keepout** (spaces
     included) so brick cannot peek through gaps.
   - Pack as ~3 columns, ~1.25 mm mono height, horror-vacui density.

3. **LOGO** — Mascot pixel silhouette (eyes/mouth cut out — white face pixels
   in `src/images/mascot_16.png` are open FR4) + wordmarks
   **PuzzlePocket** / **PuzzleScript**.
   - Front: to the right of UP.
   - Back: under-cell area, left side.
   - Optional typed player sprite block on front (logo-adjacent).
   - Close keepouts (inflated mascot pixels + text boxes), not a giant slab.

4. **LABELS** (highest) — Functional legends; keepouts clear BG+rules+logo ink.
   - Front: `<` `^` `V` `>` at the d-pad; **POWER** / **MUTE** at slides.
   - Back: per-pin JST legends **north of** each connector (readable after
     placement), vertical columns, width &lt; 1.25 mm pitch so neighbours do
     not erase each other. Format `1·3V3` (no space gap).

### Back connector pinout (labels)

| Ref | Pins (1→N, after B.Cu flip as drawn) |
|---|---|
| `J_I2C` | 3V3, GND, SCL, SDA |
| `J_EXP` | INT, NC, NC, NC (only INT routed today) |
| `J_BAT_IN` | BAT+, GND |
| `J_BAT_OUT` | BAT_SW, GND |

## Non-goals

- Collision-layer `=======` decoration.
- Unicode arrows (use PuzzleScript `<^V>`).
- Showing the internal name “pocket card”.
- Greyscale / multi-tone silk.

## Generation

- `hardware/pocket_card/case/silk.py` emits KiCad `gr_rect` / `gr_text` on
  `F.SilkS` / `B.SilkS` in the same device coordinates as footprints.
- `pcb.py` includes that output in the headless board sexpr.
- `gen_silk_preview.py` + `out/silk_preview.html` remain the visual check;
  keep them consistent with this stack when changing packing.

## Acceptance

- Both sides show brick under open FR4; no brick/rule seep through rule
  bboxes, logo, or labels.
- IO pin names visible with connectors populated (north of bodies).
- Board regenerates from `python3 pcb.py` without a GUI session.
